# Spec: Riemann Backend & Dynamic Statistical Inference Engine (Phase 1)

## Risk

**Medium.** This is a greenfield repository with no production database, live users, or irreversible external mutations. However, defects in statistical modeling (source baseline confounding, duplicate evidence across overlapping sites, truncated quadrature, fabricated rounded counts, or unstated transport assumptions), physical mechanics calculations, durable snapshot activation, or the HTTP API contract will silently emit invalid recommendations and break Phase 2 (the Windows host screen-reader and overlay client). Operational risks: upstream sites (OP.GG, CommunityDragon) may change schemas or rate-limit requests (mitigated by strict schema validation, fresh-snapshot per-adapter failure isolation, and fallback to prior valid snapshots/mechanistic priors); an unauthenticated local server must be published exclusively on host loopback `127.0.0.1:8000`; and E2E Docker tests must assert project-scoped isolated volume names (`riemann-e2e-test_*`, never an explicit shared `name:` volume) before syncing or calling `down -v`.

## Objective

Build the containerized local backend service (listening on `0.0.0.0:8000` inside Docker and published strictly to `127.0.0.1:8000:8000` on the host) for **Riemann**, a statistically rigorous dynamic recommendation engine for League of Legends **ARAM: Mayhem** and **Arena**. The backend:

1. Ingests and persists static catalogs (augments, items, champions) from CommunityDragon (`global/default/v1/` mapped to public locale `en_us`, and `global/pt_br/v1/` mapped to `pt_br`), tagged by game mode (`aram_mayhem`, `arena`), with durable atomic snapshot activation and persistence across container restarts in SQLite.
2. Aggregates external statistics via a versioned `StatsAdapter` interface (`v1`) shipping with three concrete Phase 1 adapters — **`fixture`**, **`community_json`**, and a live **`opgg`** scraper (targeting `https://op.gg/lol/modes/arena` and `https://op.gg/lol/modes/aram-mayhem` plus champion build sub-pages) — using **primary-source selection**, **source-specific baseline centering in log-odds space**, **mechanically-compatible patch discounting**, and an **exact Binomial likelihood with a constrained two-scale Normal mixture prior** integrated via **convergent adaptive deterministic quadrature** at sync time (with secondary overlapping feeds used strictly for corroboration and source-sensitivity reporting, never double-counted).
3. Computes **exact physical game mechanics** from CommunityDragon and a versioned, schema-validated **Augment-Champion-Item Relation Graph** (`data/relation_graph.json`, minimum 40 curated build-defining augments, 50 Legendary items, plus deterministic CommunityDragon tag-and-value extraction fallback), combining posterior baseline-adjusted associations with **reference-subtracted mechanistic transport adjustments** and explicit **sampling-plus-bias sensitivity envelopes** (separating mean bias robustness from full envelope separation, and never overclaiming unidentifiable causal WPA from aggregated website margins).
4. Exposes deterministic, low-latency local REST endpoints (`< 50 ms` p95 on realistic cached catalog and posterior scale, with **zero outbound network attempts** on inference routes) for multilingual OCR augment resolution (`en_us` / `pt_br`), dynamic conditional augment ranking (with post-pick item pivots), and dynamic item recommendations to be consumed by Phase 2.

## Out of Scope (Deferred to Phase 2+)

- Windows screen capture, screenshot preprocessing, OCR execution, Riot Live Client Data API (`https://127.0.0.1:2999`) polling, and transparent click-through overlay UI rendering (Phase 2).
- Multiple live third-party scrapers beyond `opgg`, or any anti-bot/CAPTCHA bypass or authenticated scraping.
- Correlated-sample GLS pooling across overlapping third-party sites (deferred unless defensible overlap covariances exist; Phase 1 uses one primary source across unverified pools + corroboration + verified disjoint-cohort pooling only).
- Sequential Bellman multi-round lookahead over future augment offers (requires verified offer probabilities $P(O' \mid S, a)$, not pick frequencies; deferred to Phase 2).
- Local match-history telemetry recording and empirical calibration of mechanistic feature weights $\beta$ on chronological match-level logs (Phase 2).
- Causal identification of mid-game gold-lead confounding or hidden-prerequisite transport mismatches (unidentifiable from aggregated website margins; explicitly documented and surfaced via sensitivity bounds rather than claimed as causal WPA).

## Decisions

1. **Phased separation (Docker inference backend in Phase 1; Windows capture/overlay host client in Phase 2).**
   - *Reason:* A Linux Docker container on Windows cannot capture the desktop screen or draw a click-through overlay over League of Legends. Establishing the statistical core and OpenAPI contract first gives Phase 2 a deterministic local API on `127.0.0.1:8000`.
2. **Python 3.12 + FastAPI + Pydantic v2 + SQLite (project-scoped Docker volume, durable atomic snapshot activation).**
   - *Reason:* FastAPI provides typed request/response contracts and OpenAPI export; SQLite delivers durable single-file persistence across container restarts with transactional rollback on invalid syncs and zero extra containers. Using an unnamed Compose volume (`riemann_sqlite: {}`) ensures each Compose project gets an isolated volume name (`<project>_riemann_sqlite`).
3. **One primary source across unverified pools + source-specific log-odds centering + corroboration (no guessed-covariance GLS).**
   - *Reason:* Different websites have different baselines (e.g., Lolalytics ~51.8% vs OP.GG ~50%) and scrape overlapping subsets of the same Riot match pool. Guessing overlap correlations in GLS can produce non-PSD matrices and negative pooling weights. Selecting one primary source across all unverified sources, pooling only explicitly verified disjoint `overlap_group`s, centering against each source's matched baseline, and routing secondary overlapping feeds to same-patch corroboration prevents both baseline shift bias and sample double-counting.
4. **Exact Binomial likelihood + constrained two-scale Normal mixture prior via convergent adaptive deterministic quadrature at sync.**
   - *Reason:* Haldane-Anscombe Normal approximations break on sparse counts like `2/2`, fixed-strength Beta shrinkage over-shrinks heavy-tailed synergies, and fixed grids truncate extreme posteriors. Dynamically bracketing $\hat{\delta}_{\text{MAP}}$, expanding integration tails until boundary density falls below `1e-12` of peak, and refining spacing until halving changes `E[delta]`, `q05`, `q95`, and `E[sigma(b*+delta)]` by `< 1e-6` guarantees accuracy across the entire valid domain (`baseline_rate in [0.001, 0.999]`) without brittle hardcoded node counts.
5. **Exact physical mechanics first + reference-subtracted composite score $R_e(S) = E_q[\delta_e] + (h(S,e) - h(S_{\text{ref}},e))$ + explicit transport & sensitivity reporting.**
   - *Reason:* Aggregated marginals cannot identify conditional interactions or causal WPA. Computing physical quantities first (cooldown $C(H)$, usable vs. wasted crit, explicit converter output, *Weapon of Destiny* binding/transform/sold-state history), setting $m_e = h(S_{\text{ref}}, e)$, and expressing every breakdown term as a delta relative to $S_{\text{ref}}$ guarantees `mechanistic_delta_logit == 0.0` at $S_{\text{ref}}$ (even for a self-overcapping candidate) and clean fallback to $h(S, e)$ when no data exists.
6. **Fresh-snapshot per-adapter failure policy and durable activation marker.**
   - *Reason:* Carrying forward stale stats from an older snapshot when an optional adapter fails during a new catalog sync risks dangling entity references. Each sync builds a fresh complete snapshot (`0` rows from a failing optional adapter, status `"error"`). SQLite records a single durable `active_snapshot` pointer inside the final commit transaction; if the subsequent in-memory cache swap fails, sync returns `500`, `/health` reports `degraded_cache_reload_required`, live requests continue serving the prior immutable in-memory pointer until restart, and restart loads the durably committed `active_snapshot` cleanly.
7. **Live `opgg` adapter (`opgg_schema_v1`) with exact Decimal rounded-count recovery and separate live smoke verification.**
   - *Reason:* OP.GG's Arena (`/lol/modes/arena`) and ARAM: Mayhem (`/lol/modes/aram-mayhem`) pages publish SSR payloads. The adapter uses polite rate limiting (`>= 0.5 s` delay, `10 s` timeout, zero CAPTCHA bypass), never fabricates counts from ambiguous rounded percentages or tier letters, is unit-tested offline against versioned synthetic fixtures, and is verified separately against live OP.GG via `scripts/smoke_live_opgg.py` reporting extracted fields for both modes.
8. **CommunityDragon locale mapping (`en_us -> default`, `pt_br -> pt_br`), dedicated `entity_translations` table, and deterministic `rapidfuzz` OCR matching.**
   - *Reason:* CommunityDragon serves English assets under `global/default/v1/` and Portuguese under `global/pt_br/v1/`. Storing translations in `entity_translations(entity_type, canonical_id, locale, display_name, normalized_name)` prevents key collisions with modes. Applying uppercase `I -> l` folding *before* lowercasing makes confusable folding actually operative.

## Mathematical Specification

### 1. Observation Schema (`StatsAdapter` v1), Validation, and Source Selection

`StatsAdapter` v1 exposes `adapter_id: str`, `schema_version: "v1"`, `overlap_group: str`, `source_priority: int`, `is_disjoint_verified: bool`, and returns `AdapterPayload(catalog_patch_hint: str | null, observations: list[Observation], adapter_metadata: dict)`. Both `community_json` (reading a versioned JSON file `{"schema_version": "v1", "source_id", "overlap_group", "source_priority", "is_disjoint_verified", "observations": [...]}`) and `opgg` emit this identical schema.

Every observation row is uniquely keyed by `(source_id, cohort_id, mode, metric_type, patch, champion_id, entity_type, entity_id, slot_key)`:

- **Stratum definition:** `stratum = (champion_id, entity_type, entity_id, slot_key)` where `slot_key` is `"slot_1"`..`"slot_6"` or `"all"`. Rows with `slot_key="all"` are NEVER pooled with `"slot_k"` rows. When `slot_index=k` is requested, the engine uses `"slot_k"` if present, else falls back to `"all"` (`selection_bias_warning = True`); when `slot_index=null`, the engine uses `"all"` (`selection_bias_warning = True`).
- **Binary outcomes (`win` for `aram_mayhem`; `top4` and `top1` for `arena`):**
  - Requires finite integer `games >= 1`, `0 <= wins <= games`, and matched source baseline: either raw counts (`baseline_games >= 1`, `0 <= baseline_wins <= baseline_games`, producing smoothed rate `(baseline_wins + 0.5) / (baseline_games + 1.0)` restricted to `[0.001, 0.999]`), or explicit `baseline_rate in [0.001, 0.999]`. If BOTH raw baseline counts and `baseline_rate` are provided, validate `abs(baseline_wins / baseline_games - baseline_rate) <= 1e-4` (else reject `conflicting_baseline_fields`) and use raw counts.
  - **Exact Decimal rounded-rate recovery:** When an upstream source publishes a rounded proportion string `rate_str` (with `rate_decimals` digits after the decimal point and rounding mode `ROUND_HALF_UP` or `ROUND_HALF_EVEN`) and integer `games`: using exact `Decimal` arithmetic, enumerate candidate integers `w in [max(0, floor((rate - 10^-d)*games)), min(games, ceil((rate + 10^-d)*games))]` whose quantized `Decimal(w) / Decimal(games)` equals `Decimal(rate_str)`. Accept `wins = w` **only if** exactly one integer `w` matches; otherwise reject the row with adapter warning `ambiguous_rounded_count`. Tier letters (`S`/`A`/`B`) are stored only as non-statistical `curated_tier` metadata.
  - **Baseline consistency & cohort identity:** All rows sharing `(source_id, cohort_id, mode, metric_type, patch, champion_id, slot_key)` must agree on baseline rate within `1e-6` (else reject `conflicting_reference_baseline`). `entity_equals_reference_cohort: bool = False` may be `True` **only** when raw baseline counts are present AND `wins == baseline_wins` AND `games == baseline_games` (divergent counts with `entity_equals_reference_cohort=True` fail validation with `invalid_cohort_identity`).
  - **Duplicate keys & metric isolation:** Duplicate primary keys within an adapter payload fail validation (`duplicate_observation_key`). Incompatible `metric_type` values (`win`, `top4`, `top1`, `avg_placement`) are never pooled.
  - **Optional `pick_rate`:** Defined explicitly as `entity_games / champion_stratum_games` (`in [0, 1]`) when `champion_stratum_games` is reported; `null` otherwise.
- **Continuous Arena placement (`avg_placement` for `arena` only):**
  - Schema fields: `games >= 1`, `mean_placement in [1.0, 8.0]`, matched `baseline_mean_placement in [1.0, 8.0]` (default `4.5`).
  - Per-patch discounted centered shrinkage toward the most recent compatible patch's baseline $\bar{r}_{\text{ref}}$ (default `4.5`), with per-patch delta $\Delta r_p = \bar{r}_{e,p} - \bar{r}_{0,p}$ and prior weight $M_{\text{place}} = 100$:
    $$\hat{r}_e = \operatorname{clip}\!\left(\bar{r}_{\text{ref}} + \frac{\sum_p d_p n_p \Delta r_p}{\sum_p d_p n_p + M_{\text{place}}},\; 1.0,\; 8.0\right)$$
    Reported strictly in `arena_secondary.avg_placement`, never mixed into binary log-odds.
- **Primary source selection & overlap isolation:**
  - Partition all observations for a `(mode, metric_type, patch, stratum)` into:
    1. **Verified disjoint groups** (`is_disjoint_verified == True`): within each distinct `overlap_group`, select one primary `(source_id, cohort_id)` by `(source_priority ASC, source_id ASC, cohort_id ASC)`. Each selected verified disjoint group contributes an independent likelihood factor.
    2. **Unverified pool** (all observations with `is_disjoint_verified == False`, regardless of their `overlap_group` string): treated as ONE shared potentially-overlapping pool — select **at most one** overall primary `(source_id, cohort_id)` by `(source_priority ASC, source_id ASC, cohort_id ASC)`. All remaining unverified observations are excluded from the likelihood and routed to `corroboration`.
  - **Same-patch corroboration:** For each secondary source $s$, let $P_{\text{shared}} = P_{\text{primary}} \cap P_s$ be the intersection of compatible patches present in both the primary source and $s$. If $P_{\text{shared}} \neq \emptyset$, compute $E_{q,s}[\delta_e]$ and $E_{q,\text{prim}}[\delta_e]$ over the **same** patch set $P_{\text{shared}}$ under the same prior; `max_source_disagreement_logit = max_s |E_{q,s} - E_{q,\text{prim}}|`; `status = "no_secondary"` if no secondary shares compatible patches, `"divergent"` if `max_source_disagreement_logit > 0.15`, else `"aligned"`.

### 2. Source-Centered Exact Binomial Likelihood & Convergent Adaptive Quadrature

Let $\operatorname{logit}(p) = \ln\bigl(\frac{p}{1-p}\bigr)$ and $\sigma(\eta) = \frac{1}{1+e^{-\eta}}$.

For entity $e$ on `(mode, champion, primary binary metric, stratum)` across patches $p$ in the versioned `patch_calendar` (newest patch has `age(p) = 0`; unknown patches fail sync validation):

1. **Mechanically compatible patch discount ($d_p$):**
   $$d_p = \mathbf{1}\{\text{patch } p \ge \max(\text{rework\_patch}(c),\, \text{rework\_patch}(e),\, \text{mode\_rework\_patch}(m))\} \cdot \lambda^{\operatorname{age}(p)}, \qquad \lambda \in (0, 1) \text{ (default } 0.7)$$
   If rework truncation excludes all observations (so $\sum_p d_p n_p = 0$), the entity cleanly evaluates under the zero-data prior ($E_q[\delta_e] = m_e$, $N_{\text{eff}} = 0$).
2. **Matched source baseline logit ($b_p$) & baseline-uncertainty disclosure:**
   - If ALL surviving observations carry `entity_equals_reference_cohort == True`, return degenerate exact identity $\delta_e \equiv 0.0$ (`association_mean_logit = 0.0`, `association_ci_90_logit = [0.0, 0.0]`). If only a subset carry `entity_equals_reference_cohort == True`, exclude those identity rows (`d_p = 0`) and evaluate remaining rows normally.
   - Otherwise $b_p = \operatorname{logit}(\mu_{s,p,h}) \in [\operatorname{logit}(0.001), \operatorname{logit}(0.999)]$.
   - *Baseline uncertainty disclosure:* All posterior intervals `association_ci_90_logit` are explicitly **conditional on the fixed matched baseline $b_p$**; when raw `baseline_games < 50`, emit warning `low_baseline_sample` and elevate policy bound $B_{\text{base}}$ to `0.12`.
3. **Constrained Two-Scale Normal Mixture Prior ($g_e(\delta)$):**
   $$g_e(\delta) = \pi\,\mathcal{N}(\delta;\, m_e,\, \tau_{\text{small}}^2) + (1 - \pi)\,\mathcal{N}(\delta;\, m_e,\, \tau_{\text{large}}^2)$$
   Defaults: $\pi = 0.90$, $\tau_{\text{small}} = 0.10$, $\tau_{\text{large}} = 0.50$ ($0 < \tau_{\text{small}} < \tau_{\text{large}}$), $m_e = h(S_{\text{ref}}, e)$.
4. **Convergent Adaptive Deterministic Quadrature Contract:**
   $$\log \tilde{q}_e(\delta) = \log g_e(\delta) + \sum_{p} d_p \Bigl[w_p \log\sigma(b_p + \delta) + (n_p - w_p)\log\bigl(1 - \sigma(b_p + \delta)\bigr)\Bigr]$$
   - Dynamically bracket the posterior mode $\hat{\delta}_{\text{MAP}}$ (expanding symmetrically around $m_e$ until the log-posterior derivative changes sign) and converge $\hat{\delta}_{\text{MAP}}$ to `< 1e-8` via golden-section / Brent search.
   - Expand integration bounds `[lo, hi]` around $\hat{\delta}_{\text{MAP}}$ and $m_e$ until boundary density satisfies $\exp(\log\tilde{q}(\text{bound}) - \log\tilde{q}(\hat{\delta}_{\text{MAP}})) < 10^{-12}$.
   - Integrate with log-sum-exp stabilized adaptive composite quadrature (broad + curvature-refined local mesh), verifying grid convergence: halving mesh spacing changes `E_q[delta]`, `q_05`, `q_95`, and `E_q[sigma(b* + delta)]` by `< 1e-6`.
5. **Precomputed Posterior Summaries:**
   - `association_mean_logit` = $E_q[\delta_e]$, `association_ci_90_logit` = `[q_05, q_95]` (conditional on fixed $b_p$)
   - `standardized_wr_delta` = $E_q[\sigma(\operatorname{logit}\mu_* + \delta_e)] - \mu_*$ ($\mu_* = 0.50$ for `win`/`top4`)
   - `arena_secondary.top1_rate` = $E_{q,\text{top1}}[\sigma(\operatorname{logit}(0.125) + \delta_{\text{top1}})]$ (`null` if no `top1` data)
   - `effective_sample_size` = $\sum_p d_p n_p$ (primary + verified disjoint cohorts only).

### 3. Physical Mechanics Engine, Reference-Subtracted Composite Score, and Sensitivity Reporting

1. **Documented Reference State ($S_{\text{ref}}$):** Same `(mode, champion c)` with `chosen_augments = []`, `current_items = []`, `observed_crit_chance = None`, `augment_bindings = None` ($H = 0$, $\text{crit}_{\text{before}} = 0$, *Weapon of Destiny* inactive).
   *Transport assumption:* Subtracting $h(S_{\text{ref}}, e)$ removes empty-state baseline mechanical value so it is never double-counted with $E_q[\delta_e]$, but cannot remove conditional synergies already embedded inside marginal website populations; residual transport discrepancy is represented via policy bound $B_e$.
2. **Exact Physical Quantities ($\phi(S, e)$):**
   - **Item Haste (*Apex Inventor*):** $H = \sum_{a \in A_{\text{chosen}}} \text{item\_haste}(a) \ge 0$. For item $x$ with `base_cooldown_s` $C_0 > 0$:
     $$C(H) = \frac{C_0}{1 + H/100}, \qquad \text{cdr}(H) = \frac{H}{100 + H}, \qquad r_{\text{act}}(H) = \frac{1 + H/100}{C_0}$$
     Engineering score weight: $\theta_{\text{haste}}(x \mid S) = w_{\text{cd}}(x) \cdot \frac{H}{100 + H}$ (zero if `has_item_cooldown` is false).
   - **Crit & Converter Mechanics:** Let $\text{crit}_{\text{before}} = \text{observed\_crit\_chance}$ if provided, else $\text{crit}(A_{\text{chosen}}) + \text{crit}(I_{\text{current}})$, and $\text{crit}_{\text{after}} = \text{crit}_{\text{before}} + \text{crit}(e)$.
     - Each entity with `crit_overflow_converter` defines `converter_specs: [{"stat_name": str, "units_per_crit_fraction": float > 0}]` (e.g., `senna`: `{"stat_name": "lifesteal_fraction", "units_per_crit_fraction": 0.35}`).
     - Let $C_{\text{before}}$ be active converters from `{c} U A_chosen`, and $C_{\text{after}} = C_{\text{before}} \cup C(e)$.
     - If $C_{\text{after}} = \emptyset$:
       $$\text{usable\_crit\_added} = \min(1.0, \text{crit}_{\text{after}}) - \min(1.0, \text{crit}_{\text{before}})$$
       $$\text{wasted\_crit\_added} = \max(0.0, \text{crit}_{\text{after}} - 1.0) - \max(0.0, \text{crit}_{\text{before}} - 1.0)$$
       $$\psi_{\text{overcap}}(e \mid S) = k_{\text{crit}} \cdot \text{wasted\_crit\_added} \qquad (\text{default } k_{\text{crit}} = 0.32)$$
       `converted_overflow_stats = {}`.
     - If $C_{\text{after}} \neq \emptyset$: `wasted_crit_added = 0.0`, $\psi_{\text{overcap}} = 0.0$; for each `stat_name` summed across active converters:
       $$\Delta \text{conv}_{\text{stat}} = \max(0, \text{crit}_{\text{after}} - 1.0)\!\sum_{u \in C_{\text{after}}(\text{stat})} r_u \;-\; \max(0, \text{crit}_{\text{before}} - 1.0)\!\sum_{u \in C_{\text{before}}(\text{stat})} r_u$$
   - **Weapon of Destiny State Machine:** Active only when an augment in $A_{\text{chosen}}$ carries `empowers_first_legendary`.
     - `augment_bindings` carries optional `weapon_of_destiny_item_id: str | null` and `weapon_of_destiny_state: "auto" | "open" | "locked" | "sold_or_unknown"` (default `"auto"`).
     - Contradictory combinations return `422` (`contradictory_augment_binding`): `weapon_of_destiny_state == "open"` with `weapon_of_destiny_item_id is not None`.
     - Resolution order:
       1. If `weapon_of_destiny_state == "sold_or_unknown"`: emit `weapon_of_destiny_state_unknown`, set $\theta_{\text{wod}} = 0.0$.
       2. Else if `weapon_of_destiny_item_id` is provided: check direct match in `current_items` or descendant match via validated acyclic `transformed_from` DAG. If `0` matches appear in `current_items` (item sold/absent), emit `weapon_of_destiny_state_unknown` and set $\theta_{\text{wod}} = 0.0$; if `>= 2` descendants appear, emit `weapon_of_destiny_transform_ambiguous` and set $\theta_{\text{wod}} = 0.0$; if `1` match appears, lock to that item.
       3. Else (`weapon_of_destiny_item_id is None`): let $L_{\text{owned}}$ be owned Legendary items.
          - If $|L_{\text{owned}}| == 1$: unambiguously locked to $L_{\text{owned}}[0]$.
          - If $|L_{\text{owned}}| \ge 2$: emit `weapon_of_destiny_binding_ambiguous`, set $\theta_{\text{wod}} = 0.0$.
          - If $|L_{\text{owned}}| == 0$: if `weapon_of_destiny_state == "locked"` OR (`weapon_of_destiny_state == "auto"` and `slot_index is not None and slot_index >= 2`), emit `weapon_of_destiny_state_unknown` and set $\theta_{\text{wod}} = 0.0$; else (`"open"`, or `"auto"` with `slot_index in {None, 1}`) slot is **open**.
     - Open slot + `is_legendary(x)`: $\theta_{\text{wod}}(x) = B_{\text{rush}} \cdot \text{stat\_scaling\_tier}(x, c)$ ($B_{\text{rush}} = 0.16$), emitting `weapon_of_destiny_first_legendary`; non-Legendary gets `0.0`.
     - Locked to $x_{\text{locked}}$: rush bonus is `0.0`; candidates with `amplifies_locked_legendary` edge targeting $x_{\text{locked}}$ receive that edge weight ONLY in `weapon_destiny_logit` (excluded from `item_graph_logit`).
   - **Relation Graph Edge Deduplication:**
     - Symmetric `augment_pair_synergy`: canonical unordered key `(edge_id, min(a1, a2), max(a1, a2))`.
     - Directed `context_to_augment`, `augment_item_synergy`, `item_pair_synergy`: key `(edge_id, source_entity_id, target_entity_id)`.
3. **Reference-Subtracted Composite Score & Exact Algebraic Breakdown:**
   Every breakdown component represents a delta relative to $S_{\text{ref}}$:
   - `overcap_penalty_delta_logit = psi_overcap(e | S) - psi_overcap(e | S_ref)` (so even a synthetic `+1.25` crit candidate has `overcap_penalty_delta_logit == 0.0` at $S_{\text{ref}}$!)
   - **Augments:** `mechanistic_delta_logit = pair_synergy_logit + context_synergy_logit - overcap_penalty_delta_logit`
   - **Items:** `mechanistic_delta_logit = item_haste_logit + weapon_destiny_logit + item_graph_logit - overcap_penalty_delta_logit`
   - **Both:** `composite_score = association_mean_logit + mechanistic_delta_logit` (`prior_mean_logit = h(S_ref, e)` is reported separately as prior metadata, never added twice).
4. **Sensitivity Envelope & Two-Tier Robustness Indicators:**
   - `B_base` precedence (maximum applicable): `0.12` if (`N_eff == 0` OR `pick_rate < 0.02` OR `baseline_games < 50`), else `0.08` if `slot_key == "all"`, else `0.05`.
   - `B_e = B_base + (max_source_disagreement_logit if corroboration.status == "divergent" else 0.0)`.
   - `sensitivity_envelope_logit = [q_05 + mechanistic_delta_logit - B_e, q_95 + mechanistic_delta_logit + B_e]`.
   - Against runner-up $e_2$ (`null` for the last item):
     - `mean_bias_margin = (composite_score_1 - composite_score_2) - (B_1 + B_2)` -> `is_bias_robust_on_means = (mean_bias_margin > 0.0)`
     - `envelope_gap = sensitivity_envelope_logit_1[0] - sensitivity_envelope_logit_2[1]` -> `is_envelope_separated = (envelope_gap > 0.0)`.

## API Contract (Consumed by Phase 2)

- **Networking:** Uvicorn binds `0.0.0.0:8000` inside Docker; `docker-compose.yml` publishes `127.0.0.1:8000:8000` only and declares an unnamed project-scoped volume `riemann_sqlite: {}` (never a hardcoded shared `name:`).
- **Deterministic tie-breaker:** `(-round(composite_score, 9), -round(effective_sample_size, 6), canonical_id)`.
- **Normalized error format** (all `4xx`/`5xx`, including Pydantic 422 handlers): `{"code": str, "detail": str, "field": str | null, "active_snapshot_preserved": bool | null}`.
- **Empty-volume startup:** `GET /health` returns `200` (`status="degraded_empty_catalog", snapshot_id=null, catalog_patch=null`); `GET /v1/catalog/status` returns `200` (`snapshot_id=null, catalog_patch=null, graph_version=null, counts=empty_zeros, adapters=[]`); `/v1/resolve/*` and `/v1/recommend/*` return `503` (`code="snapshot_not_ready"`).
- **Durable atomic snapshot & concurrency:** SQLite maintains a single-row `active_snapshot` pointer updated atomically inside the final commit transaction. All requests read one immutable in-memory snapshot pointer swapped atomically after SQLite commit. If the in-memory swap fails post-commit, sync returns `500` (`code="cache_swap_failed", active_snapshot_preserved=true`), `/health` reports `status="degraded_cache_reload_required"`, live requests keep serving the prior in-memory snapshot until restart, and process restart loads the latest durably committed `active_snapshot` from SQLite. Concurrent `POST /v1/catalog/sync` calls serialize via an async lock (`409`, `code="sync_in_progress"`).

### Endpoints

- `GET /health` -> `200`: `{"status": "ok"|"degraded_empty_catalog"|"degraded_cache_reload_required", "snapshot_id": str|null, "catalog_patch": str|null, "modes": ["aram_mayhem", "arena"]}`
